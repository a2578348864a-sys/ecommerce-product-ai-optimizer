# Core-Smoke-Fix.1 — learnings

1. **有限样本规律 ≠ 永久报表合同**：12/12 CC 样本 BSR∈[1..10] 只是样本规律，官方存在 Top100/Top400/加载更多导出场景（CC BSR 可 >10）。把「CC BSR 必 ≤10」升级为合同并推导「BSR>10 ⇒ PS」，是把概率规律当成确定性逻辑——独立复核撤销。**教训：判定类契约必须有官方文档/规范支撑；样本规律只能做辅助信号。**

2. **结构同构是 fail-closed 的硬理由**：无搜索排名列的 CC 与 PS 新格式表头完全相同（72 列、四工作表），不存在 deterministic 结构差异——这正是「无搜索排名一律人工选择」的第一性依据。**教训：先穷举确定性结构差异；没有差异就 fail-closed，不强行用弱信号补。**

3. **multi-signal 与 validated 的差距**：BSR 值域/单类目/月销高/BestSeller 多在 13 份样本上区分度 100%，但存在已知反例（热销搜索词 PS 可全中榜单特征；Top100 CC 可 BSR>10），达不到 validated 级。**教训：自动判定与辅助建议必须分层——建议可被用户推翻，判定必须 fail-closed。**

4. **对抗样本要针对"误判方向"**：复核要求「CC BSR>10 不得判 PS」——新增 cc-bsr-beyond-band 对抗用例（单类目 + BSR 11..100 + 月销高 + BestSeller 多），断言 unknown + 显式 CC 放行。**教训：golden 不只验证正例，要验证规则边界上的反例。**

5. **precheck fail-closed 时行数据仍可用于诊断**：reportType unknown 时 precheck 行全拒（acceptedRows=0）但 rejectedRecords[].raw 保留原始行值——多信号建议基于 raw 计算，无需改 precheck 的解析行为。**教训：诊断层与判定层解耦，复用既有 fail-closed 输出的残余信息。**

6. **显式选择的语义随强证据变化**：旧规则「自动判定成功且与显式冲突 → mismatch 拒绝」依赖"强证据"存在；新规则无搜索排名无强证据 → 显式选择结构合法即放行。确定性冲突（含搜索排名 vs 显式 CC）仍拒绝。**教训：mismatch 拒绝只适用于确定性证据，不确定场景人工选择必须放行。**

7. **问题 2/3 的修复经受住复核**：并行优化（实测 51.2s→21.0s）+ 渐进 UI、统一 eligibility 权威判断均被独立复核确认为 PASS，未重构——说明「先实测再改」与「单一权威判断」是正确工程姿势。
