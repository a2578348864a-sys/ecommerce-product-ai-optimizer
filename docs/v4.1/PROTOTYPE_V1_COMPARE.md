# 视觉样板 v1（本地 Owner）—— 新旧对比说明

> 本轮停止标准达到：只新增原型（app/prototype/** + 快照/文档）；未改公网/Replay/Visitor/业务/API/DB；未 push/tag/部署。

## 一句话问题

上一版把工程后台换成了中文卡片，但页面仍围绕「Run、状态、缺口、检查、调试」组织，普通卖家看到的还是流程状态机。

## 新版设计方向

- 概念：上架前的商品核验台——像货主面前的一张张货单，而不是流程控制台。
- 记忆点（签名）：结论贴纸——每张卡右上角一枚撕边贴纸（先补资料=琥珀 / 研究中=蓝灰 / 已完成=墨绿），一眼读懂「现在轮到谁、下一步是什么」。
- 调色：纸白台面 #F6F5F2 · 墨绿印台 #174A3A · 琥珀待办 #B07C1E · 炭字 #24272B · 蓝灰 #5F6B7C · 警示红 #8C3A2B（刻意避开奶油/黑+荧光/报纸三种默认风）。
- 字体：标题/商品名=思源宋体（印刷货单感，克制使用）；正文=系统黑体；说明=细灰小字。
- 布局：桌面三栏分组；390 纵向 + 底部导航（研究台 / 商品研究），无横向导航。

## 新旧对比（逐项）

| 维度 | 上一版（C 端化第一轮） | 本版样板 |
|---|---|---|
| 组织单位 | Run（运行）+ 状态分组 | 商品项目（同商品 14 次研究合并为 1 张卡） |
| 首页首屏 | 标题+四状态区（含调试折叠） | 一个主按钮「开始研究一个商品」+ 三组「需要我处理 / AI 研究中 / 已完成」 |
| 卡片信息 | 名称/关键词/市场/状态/缺口/下一步（工程投影） | 占位图 / 商品名 / 一句话结论 / 结论贴纸 / 唯一下一步按钮 |
| 结论呈现 | 状态徽标+缺口文本 | 一句人话（例：已拿到 1 条市场依据；评论与数据还没拿到，先补充再判断。） |
| 结果页 | 六 Tab（含操作记录/调试） | 首屏结论卡（图/名/市场·关键词/结论贴纸/原因/唯一按钮）+ 仅四个业务模块 + Listing 与图片（有结果直接展示；不可用给原因+唯一操作） |
| 空状态 | 空检查卡片/「尚未生成」 | 模块缺资料只显示「AI 结论（暂无原因）+ 缺什么 + 去补充按钮」，无空检查卡 |
| 术语 | 曾残留英文枚举 | 页面零 V4/Run/Gate/Evidence/blocked/no_results/rev/UUID/调试详情/内部码（浏览器审计 0 命中） |
| 移动端 | 横向导航+卡片 | 底部导航两项；390 无横向滚动、无截断（实测 overflow=false） |
| 数据 | 静态演示字段 | 真实快照（dev.db 只读聚合：商品 Kitchen Storage / 美国站 / Listing 真实草稿标题与要点 / 图片检查真实原因已转用户语言） |

## 验证（真实浏览器，非测试通过代替）

- 1440×900 与 390×844 各两页截图共 4 张（evidence/c-prototype/）；
- 术语审计：两页两档 0 命中（含 quantity_not_verifiable 等内部码，已映射为「无法确认数量」）；
- console/hydration：0 error（已修复原型起先双层 body 的 #418）；
- 5 秒三问自检：研究什么（Kitchen Storage · 美国站）→ 结论（先补资料）→ 下一步（补充市场资料），一眼可读。

## 已知限制（如实）

- 商品图：数据源无真实图片 URL → 明确占位图（线稿+「商品图待补充」）；
- 关键词：数据无关键词字段 → 显示「关键词待补充」；
- 下一步按钮为视觉占位（原型不接行为；真实承接需对应输入/接口，属后续轮次）；
- 当前数据仅有唯一商品项目（真实）；三组并存形态已按结构实现，待真实多商品数据验证。
