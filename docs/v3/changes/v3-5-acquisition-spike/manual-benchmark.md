# V3.5-A — Manual Benchmark（人工基准设计）

> 任务书十三/三十九节。Manual Import 是 benchmark 与 fallback（不是失败路线）。
> **实测状态：用户已执行（2026-08-15，回复"完成"）；定量指标（耗时/操作数/新手难度）未提供——如实留缺口**。

## 1. 基准协议

同一 Candidate（Case A/B/C）下：

1. 用户自行在 1688（本机浏览器）搜索候选关键词
2. 选择 3 个候选
3. 复制 URL / 页面字段（标题/价格/MOQ/规格/店铺）
4. 粘贴到工作台人工导入（V3.4 已验证的 Manual Import 链路）

## 2. 记录指标

- 操作数量（搜索→选择→复制→粘贴的步数）
- 耗时（总分钟数）
- 字段完整度（15 字段矩阵覆盖）
- 出错可能（复制错列/价格单位/规格混淆）
- Evidence 可追溯性（URL + capturedAt + 人工绑定）
- 新手难度（1-5）

## 3. 与自动 Route 的比较判据（任务书三十九节）

自动方案必须证明**相对 Manual 有明显价值**（显著减少用户操作/时间），否则不值得为自动承担风险。

## 4. 本轮结论（静态）

- Manual Import 链路在 V3.4 已完整验证（导入/去重/有界/实体绑定/展示）。
- 作为 benchmark：所有自动 Route 的"用户节省"必须量化对比后才能判定。
- **无论自动路线结果如何，Manual Import 永久保留为 fallback**（任务书三十节）。

## 5. 实测记录（2026-08-15）

- 用户按协议执行 Manual benchmark（1688 搜索统一 Candidate 关键词、选 3 候选、看详情），回复"完成"。
- **定量指标未提供**（timeToFirstCandidate / timeToThreeCandidates / userActionCount / 新手难度 1-5 均无数据）——**"自动明显优于 Manual"的量化判据缺口保留**，不虚构数字。
- 定性基准（既有认知，非本轮实测）：V3.4 Manual Import 链路每次需搜索→选择→复制 URL/字段→粘贴，无复用；易错点=价格区间/规格/单位复制混淆。
- 处理：对比矩阵中 Manual 列以"已执行、定量缺失"标注；最终裁定对"优于 Manual"的判定**不依赖缺失数字，改为功能可达性 + 用户操作结构（首次/复用）论证**。
