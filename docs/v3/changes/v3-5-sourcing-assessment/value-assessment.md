## 2. PROFIT_MODULE 结论（任务书三十六节）

**PROFIT_MODULE = ASSUMPTION_ONLY（Calculator）**

- 当前 Evidence 不支持真实利润计算（真实采购成交价/国际物流/头程/仓储/平台费/汇率/损耗均不可得——任务书十九节）。
- 若未来保留旧利润计算器（lib/profit.ts，manual_profit_mvp），它只能是**用户手工输入假设的计算器**：用户输入采购价/物流/平台费用 → 系统做算术 → 明确标注"基于用户假设，非真实数据"。
- **禁止**：AI 自动填参数、AI 输出利润结论、把页面价当采购价输入计算器。
- 允许的唯一结论形式：A（完全不支持）或 B（assumption-only）；**不选 C**。

## 3. 小白价值测试（任务书二十一节，10 问演练）

假设用户完全不懂供应链，看 3-5 个 1688 候选（Case A/B/C 的展示形态）：

1. 哪几个看起来最接近目标商品？→ **能**（形态/功能 ✓/✗/? 标记）
2. 为什么？→ **能**（matchEvidence 逐条说明）
3. 哪些规格不同？→ **能**（Case B 容量 ✗ 明确展示）
4. 页面价格是多少？→ **能**（displayedPrice 原文 "¥18–26"）
5. 这个价格能不能当真实成本？→ **能**（UI 明示"页面价 ≠ 采购成本；真实成本需询盘"）
6. MOQ 是多少？→ **能**（displayedMOQ 原文 + "语义需确认"标注）
7. MOQ 是否确定？→ **能**（CONDITIONAL/unknown 标注）
8. 哪些页面信息只是供应商自述？→ **能**（Seller Claim 角标）
9. 下一步应该向供应商问什么？→ **能**（manualConfirmationRequired 清单）
10. 当前还不能判断什么？→ **能**（unknowns 清单）

**判定**：不会出现"供应商 A 综合评分 89"形态 → **小白价值测试 PASS（设计层面）**。
唯一前提：候选数据由用户人工提供（当前登录墙环境下的必然路径）。

## 4. AI 合理角色（任务书二十三节）

**允许**：中文页面解释成小白语言 / 多候选差异提取 / unknown 解释 / 生成待确认问题 / 总结已有证据。
**禁止**：宣称供应商可靠 / 宣称同款 / 宣称真实成本 / 宣称有利润 / 宣称适合出口 / 宣称合规 / 自动推荐采购。
无 Evidence 就 unknown（复用 V3.4 evidenceRefs/fail-closed 模式）。

## 5. 询盘问题生成价值（任务书二十二节）

- **有价值且低成本**：根据缺失 Evidence（目标规格单价/MOQ/定制/包装/样品费）生成结构化询问清单（Question Generation，非自动联系）。
- 案例已验证（Case A/B/C 的 manualConfirmationRequired 自然产出）。
- 与 V3 一致性高（同"下一步最值得研究什么"的 Evidence 缺口模式）。

## 7. 搜索/匹配来源评估（任务书二十六节）

| 方式 | 成功率 | 依赖 | 真实性 | 自动化成本 | 风险 | 小白难度 |
|---|---|---|---|---|---|---|
| 关键词搜索（用户手动） | 中 | 用户操作 | 中 | 无 | 低 | 低 |
| 中文关键词转换 | 中 | 翻译质量 | 中 | 低（工具） | 低 | 低 |
| 图片搜同款 | 中 | 平台能力 | 低 | 高 | 高 | 低（但误导风险高） |
| 用户自己搜后贴 URL | 中高 | 用户操作 | 高 | 无 | 低 | 中 |
| 浏览器当前页采集 | 中 | 登录会话 | 中 | 中 | 中 | 中 |
| 第三方 API | 中 | 商业服务 | 中 | 高（成本） | 中 | 低 |

**结论**：推荐「用户自己搜后贴 URL」（真实、可追溯、零自动化）；中文关键词转换可作辅助工具（LATER）；图片搜同款不实施。

## 8. 总体判断

- **NARROW_APPROVAL 方向明确**：只有"人工导入供应线索 + 页面快照 + 匹配证据 + unknown + 询盘问题"值得做；
- 自动搜索/匹配/评分/利润/推荐全部 DO_NOT_BUILD；
- 登录墙实测强化了"最小自动化"路线；
- 需要用户独立审查后决定是否进入正式设计。
