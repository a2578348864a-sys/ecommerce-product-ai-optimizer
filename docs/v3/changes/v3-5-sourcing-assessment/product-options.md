# V3.5 — Product Options（4 种定位评估）

> 任务书八节：不要直接把模块叫"供应商分析"，先评估 4 种定位。

## 方案 A：1688 商品搜索助手

- **用户价值**：中（用户自己也能搜；价值在"帮我找"）
- **数据真实性**：低（搜索结果大量广告/非相关商品——任务书四-23；搜索本身需要登录墙后的真实会话）
- **实现复杂度**：高（搜索 = 自动采集，当前环境登录墙不可行；图片搜同款禁止实施——任务书二十六节）
- **误导风险**：高（"看起来像同款"其实规格不同——任务书四-1/2）
- **是否需要业务基础**：中
- **是否适合小白**：中（可能把不相关商品当"候选"）
- **与 V3 Evidence 架构一致性**：低（搜索是"发现"不是"证据"）
- **结论**：**不建议做**（DO_NOT_BUILD；搜索发现不是 Evidence，且自动化受登录墙阻断）

## 方案 B：Sourcing Evidence / 供应线索（优先假设）

- **用户价值**：高（回答"有哪些可能相关的 1688 商品、页面显示什么、哪些必须询盘"——任务书九节）
- **数据真实性**：中高（用户提供 URL/粘贴页面数据 → 页面快照可追溯；Seller Claim 明确标注）
- **实现复杂度**：低-中（人工导入 + 结构化保存 + Evidence Matrix；无自动采集）
- **误导风险**：低（无匹配概率评分、无利润结论；未知=unknown）
- **是否需要业务基础**：低（系统不判断"可不可靠"，只整理证据）
- **是否适合小白**：高（"下一步问什么"帮小白知道怎么核实）
- **与 V3 Evidence 架构一致性**：**高**（= Evidence Workbench 的供应侧 Evidence，与 VOC/浏览器证据同模式）
- **结论**：**值得做**（候选）

## 方案 C：供应方案比较工作台

- **用户价值**：中高（多候选对比矩阵）
- **数据真实性**：中（对比依赖各候选的页面快照；差异是 Derived Comparison）
- **实现复杂度**：中（矩阵展示 + 差异推导，本身不复杂；但依赖候选数据质量）
- **误导风险**：中（对比表可能被误读为"推荐"——需强标注"不是推荐"）
- **是否需要业务基础**：中（比较维度需人工选）
- **是否适合小白**：中高（表格直观）
- **与 V3 一致性**：中高（是 Evidence Matrix 的展示层）
- **结论**：**可作为方案 B 的展示层**（不单独立项；LATER）

## 方案 D：AI 供应商推荐

- **用户价值**：表面高，实际误导大
- **数据真实性**：低（页面证据不足以支撑"推荐可靠供应商"——任务书十八节）
- **实现复杂度**：中（AI 生成推荐容易，校准难）
- **误导风险**：**极高**（"供应商 A 综合评分 89"= 任务书二十一节 FAIL 形态；badge→可靠推导=任务书十八节禁止）
- **是否需要业务基础**：高（真实可靠性只有询盘/历史交易知道）
- **是否适合小白**：否（伪精确评分误导新手）
- **与 V3 一致性**：**低**（V3 禁止 AI 自动判断；Supplier Score 禁止——任务书三十一节）
- **结论**：**绝对不做**（DO_NOT_BUILD，MUST_NOT_REVIVE 旧"供应商推荐"）

## 综合结论

- **推荐定位：方案 B（Sourcing Evidence / 供应线索）**，展示层采用方案 C 的 Evidence Matrix 形态（不叫"比较台"以免误读为推荐）。
- 方案 A（搜索助手）与方案 D（AI 供应商推荐）**明确不做**。
- 与 V3 主链关系：作为 **Evidence Workbench 的供应侧 Evidence** 进入 Candidate → Evidence → Skill → Human Decision；**不重建** Supplier Agent → Profit Agent → Compliance Agent 旧链（任务书三十四节）。
