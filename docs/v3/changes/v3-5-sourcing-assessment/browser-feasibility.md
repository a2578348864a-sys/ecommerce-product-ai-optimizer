# V3.5 — Browser Feasibility（1688 只读探测结果）

> 探测日期：2026-08-15；方式：已有 V3.3 browser-control 隔离会话（headless，本机网络环境）。

## 1. 实测结果（probe-evidence/probe-result.json）

| 入口 | 结果 |
|---|---|
| PC 搜索页 `s.1688.com/selloffer/offer_search.htm?keywords=保温杯` | **重定向到登录墙**（`login.taobao.com` → 1688 登录页，5 次重定向，allowedFinalOrigin=false，页面标题"登录页面"，正文"使用 1688/淘宝App 扫码登录"） |
| 移动版搜索页（第二次尝试） | 重定向白名单外 → 会话 fail-closed（正确行为），未继续 |
| 商品详情页 | 未尝试（搜索入口不可用，按任务书不绕过） |

## 2. 结论

- **当前环境（海外 IP + headless）下，1688 搜索页强制登录墙**：自动读取不可行。
- 与 Amazon 详情页（公开可访问，V3.3/V3.4 已验证）形成鲜明对比：1688 对自动化访问的风控显著更严。
- **不绕过**：不自动登录、不读 Cookie、不绕 CAPTCHA、不模拟扫码。
- 1688 侧真实页面字段的"实测可得性"**无法在本环境自动验证**——只能通过以下途径：
  1. 用户手动打开 1688 页面（人工粘贴/记录，与 VOC 人工导入一致）
  2. 1688 官方开放平台 API（企业资质 + 商业授权，门槛高）
  3. 第三方聚合 API（商业服务，成本/合规需独立评估）

## 3. 对产品方向的含义

- 「Browser Connector 自动访问 1688」模式在当前环境**不可行**（登录墙）。
- 「用户提供 URL + 人工粘贴页面数据」模式**可行**（无门槛，与 VOC 降级路径一致）。
- 「官方 API」模式可行但门槛高（企业资质），适合远期评估。
- 结论：V3.5 若推进，应以**人工导入/URL 线索**为主，**不做** 1688 自动浏览器采集（除非未来环境/授权变化）。
