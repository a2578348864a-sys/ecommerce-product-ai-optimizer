# Listing Strategy Planner — 产品设计说明（面向非技术跨境电商运营）

> 状态：**仅设计，未实现**。本文只描述界面、文案与判断规则，不落地任何代码。
> 归属：本文是 `00-design-overview.md`（总控）第 5 节的展开与落地细化；字段命名沿用其 §3.2 `ListingStrategyPlan`。
> 读者：产品/前端实现者，以及需要拿本文件验收的运营。
> 目标用户画像：**非技术跨境电商运营（新手 / 小团队）**。他们不读 JSON、不懂 embedding、不关心"证据权重"。
> 他们只问四件事：**这份 Listing 凭什么这么写？我能不能信？我该点确认还是否决？我改哪里？**

---

## 0. 结论先行

### 0.1 一句话方案

> **不新增页面、不新增区块。把现有 Listing Studio 的「营销文案策略」卡原地升级为"五问策略区"，并把「转化蓝图」折叠区收编进来；全站只保留这一处主链策略界面。**

### 0.2 五条关键结论

| # | 结论 | 依据 |
|---|---|---|
| 1 | **位置＝原地升级，不是新折叠区、不是新页面** | 「营销文案策略」已占工作流导航的"02 营销策略"格位，且已持有五问中四问的原始数据；再加一块就是第 3 个重叠区 |
| 2 | **必须收编「转化蓝图」折叠区**，否则"痛点/角度/买家/禁区/排序"会各出现 2 次 | 见 §1.3 重叠矩阵 |
| 3 | **词汇复用 `CopyStrategyV1`，但"参考度"表达不复用** | 运营已见过「主表达角度 / 五点顺序 / 避免表达」这套词，重造加负担；但 `confidence: high\|medium\|low` 由硬编码正则产出（总控 §0.2 G4），属假精度，**必须换成可核对的计数与原文** |
| 4 | **`proofPoints`（卖什么）是唯一 100% 可追溯的一条，且今天只显示了数量** | 每条 proofPoint 就是一条已确认事实（`factId`/`field`/`value`/`shopperBenefit`）。当前 UI 只显示"证据点：N 条"——这是全系统最便宜、收益最高的一处补齐 |
| 5 | **"证据不足"必须是界面的一等公民**，包括"被丢弃的结论"也必须可见 | 总控 §3.4 闸门会丢弃无证据结论；静默丢弃＝用户以为自己看到了全部 |

### 0.3 三条诚实红线（贯穿全文）

1. **不展示无法核对的"可信度"**：不出现百分比评分、星级、confidence 高/中/低这类合成指标。
2. **不假装有依据**：无证据时显示"本次没有找到依据"，不用套话填空。
3. **算不出来的就不算**：无法逐条对应到具体资料时，明说"无法逐条对应"，只列出**本次实际用到的全部资料**（这部分可以 100% 断言）。

## 1. 现状核查（只读真实代码得出的事实）

### 1.1 运营今天会看到的四处"策略"界面

|---|---|---|---|
| `/listing-studio`（**V5 现役**） | `components/listing-v5/ListingStudioV5Client.tsx` | ①「营销文案策略」卡 ②「转化蓝图」折叠区 | **主链**：真实参与生成 |
| `/image-studio`（现役） | `TaskStudioPreparation` → `MarketingIntelligencePanel` + `CopyStrategyPlannerSuggestionPanel` | 「AI研究依据」+「Listing生成规划」 | **旁路**：`referenceOnly`，明确"不会自动修改 Listing" |

| 为什么买 | 策略卡「核心需求 / 痛点」· 蓝图「买家痛点」· 蓝图「购买触发」· 旁路「AI研究依据 → 用户痛点与需求」 | **4** |

**结论：五问中有 5 问重复 2 次以上。再去新增一块＝把 2 次变 3 次。**

### 1.4 数据可达性真相表（哪条能追溯、哪条不能）

这张表是全文最重要的依据。**决定了哪条结论可以挂"依据"徽标，哪条只能挂"参考"，哪条必须标"无依据"。**

| 五问 | 界面数据来源 | 今日 API 是否下发 | 可追溯性（**真实**） |
|---|---|---|---|
| ① 谁在买 | `plan.audience[]` ← `strategy.targetAudience` | ✅ 已下发 | ⚠️ **AI 模式**：由 VOC/关键词/竞品归纳，可挂"参考"；**确定性模式**：`buildListingV5Strategy()` 里是**固定常量**（"Shoppers comparing practical product options"），**必须标"无依据·固定模板"** |
| ② 为什么买 | `plan.motivations[]` / `plan.painPoints[]` ← `strategy.purchaseMotivations` + `blueprint.purchaseTriggers[].factBacked` | ✅ 已下发（含 `factBacked`/`factIdCount`） | ✅ **半可追溯**：`factBacked=true` 的可挂"依据 N 条事实"；`false` 必须标"只能说，不能保证" |
| ③ 卖什么 | `plan.sellingPoints[]` ← `blueprint.proofPoints` | ❌ **今日只下发数量 `proofPointCount`** | ✅ **100% 可追溯**：每条即一条已确认事实（字段+值+人工确认） |
| ④ 怎么排序 | `plan.bulletOrder[]` ← `blueprint.benefitOrder`（= `strategy.bulletAngles` + `primaryFactId`） | ⚠️ 蓝图侧已下发；**`strategy.bulletAngles` 未下发** | ✅ `primaryFactId` 可追溯；`shopperValue` 在确定性模式下是**硬编码常量** |
| ⑤ 不建议表达 | `plan.avoidClaims[]` ← `strategy.avoidClaims` + `blueprint.disallowedTemptations` | ✅ 已下发 | ✅ **可解释**：`disallowedTemptations` = 系统内部硬词表减去"本商品事实里出现过的词"，可逐词解释 |

### 1.5 五个必须诚实面对的技术事实

1. **证据身份在上下文边界被压平**。`lib/listingV5/context.ts` 把 VOC 参考压成 `${theme}: ${summary}` 字符串，`insightId`/`evidenceRefs`/`strength`/`reviewCount` 全部丢失；关键词只剩词本身，竞品只剩 `note || asin`。→ **"点开看证据"必须先在投影层把身份带回来**（总控 §2.3 C1），否则前端只能作假。
2. **模型被明令禁止返回证据编号**。`lib/listingV5/strategy.ts` 的 system prompt 写着 "Never output product facts, claims, **evidence, ids** or generated copy"。→ 因此**逐条证据绑定不可能来自模型**，只能由确定性闸门在冻结上下文里校验/回填（总控 C3）。
3. **确定性兜底路径在"造"市场洞察**。`strategy.ts` 的 `classifyReferenceNeeds()` 用 `messy|organize|storage|kitchen|sip|straw|leak…` 正则从 VOC 文本猜痛点，再派生出动机/场景/人群；`primaryAngle` 是 `Make ${product} easier to understand and use` 模板；`tone`、`secondaryAngles`、`bulletAngles[].shopperValue` 全是硬编码常量。→ **这些字段在确定性模式下绝不能挂证据徽标。**
4. **`benefitOrder` 与 `bulletAngles` 是同一个列表**。`conversionBlueprint.ts` 的 `benefitOrder()` 就是 `strategy.bulletAngles.map(...)` 再加一个 `primaryFactId`。→ **分两处展示＝纯重复**，必须合并成一处。
5. **强度与占比是真实可核对的**。`reviewCount` 由 `evidenceRefs` 去重后计数；`strength` 阈值明确（0–1 条＝`isolated`，2–3 条＝`weak`，≥4 条＝`recurring`，`lib/server/vocAnalysis.ts` 并注明"UI 展示规则，非行业真理"）；`coverage = reviewCount / 已分析评论数`。→ **这三项可以展示；合成可信度不行。**

## 2. 信息架构：放在哪、和谁合并

### 2.1 推荐方案 A：原地升级「营销文案策略」卡，并收编「转化蓝图」

```
模块 2（改造后）＝ 五问策略区 · 唯一主链策略界面
  ├─ ① 谁在买        ← strategy.targetAudience + blueprint.buyerIntent
  ├─ ② 为什么买      ← strategy.purchaseMotivations + blueprint.purchaseTriggers
  ├─ ③ 卖什么        ← blueprint.proofPoints（★今日只显示数量，本次补齐为可点开的事实清单）
  ├─ ④ 五点排序建议  ← blueprint.benefitOrder（= bulletAngles，合并为一处）
  ├─ ⑤ 不要写这些    ← strategy.avoidClaims + blueprint.disallowedTemptations
  ├─ ⚠ 未采用 N 条    ← plan.dropped[]（默认收起，但必须可见）
  └─ ▸ 进阶：转化细节 ← 原蓝图剩余字段（转化角度/购买疑虑/利益优先级/决策顺序）

模块 4（改造后）＝ 事实安全与人工复核
  └─ 移除「转化蓝图」折叠区（已迁入模块 2），保留校验细节 + 质量评分 + 资料更新提示
```

**理由**
- 五问本就属于"策略"，不属于"复核"。蓝图放错房间了。
- 页面区块总数**减少 1 个**，而不是增加。
- 五问按运营的提问顺序排列，符合"先看凭什么，再看写得好不好"的阅读顺序。

### 2.2 为什么不选另外两个方案

| 方案 | 做法 | 否决理由 |
|---|---|---|
| **B. 新增独立"Strategy Planner"折叠区** | 在策略卡之外新加一块 | ① 立刻变成第 3 个重叠区（§1.3 已有 5 问重复 2 次）；② 用户要在同一页两处找同一个答案；③ 违背"不新增复杂页面/区块"的约束 |
| **C. 只给现有蓝图加证据徽标** | 不动策略卡，只补蓝图 | ① 策略卡里的「目标买家/避免表达/主表达角度」仍然无依据，用户仍要跨区拼图；② 蓝图目前默认收起且混了 8 个字段，运营根本不会打开；③ 五问依旧没有统一入口 |
| **D. 把两个旁路面板也搬进 Listing Studio** | 四个面板同页 | ① 会造成"旁路建议＝已应用"的**事实性误导**（旁路面板自己写着"不会自动修改 Listing"，而策略卡是真的参与了生成）；② 直接制造第 4 个重叠区 |

### 2.3 与既有两个旁路面板的关系（回应"复用还是另造"）

**结论：复用它们的"词汇"和"外壳语言"，不复用它们的"参考度"表达，也不把它们搬进 Listing Studio。**

| 维度 | 处置 | 理由 |
|---|---|---|
| 字段词汇（`targetBuyer` / `mainAngle` / `bulletStrategies[order]` / `avoidExpressions`） | ✅ **复用** | 运营已在上线界面见过这套词；重造同义词只会加重认知负担 |
| 外壳语言（「仅供策略参考」徽标、「不会自动修改 Listing」、「仅供人工确认」、空态句式） | ✅ **复用** | 已上线且经过评审，语义已建立 |
| 分组方式（痛点与需求 / 市场表达方向 / 竞品表达趋势 / 建议结构） | 🟡 **部分复用** | 只吸收"按来源分组"这一条；分组标题改用五问口径 |
| `confidence: 高/中/低参考度` | ⛔ **不复用** | 由硬编码正则（`VOC_TOPICS`）产出，却用确定口吻显示；这是**假精度**，与"不做假可信度"直接冲突。替换为可核对的三件事：**出现条数 + 强度（中文）+ 可点开原文** |
| 面板本身是否搬进 Listing Studio | ⛔ **不搬** | 旁路 ≠ 主链。搬进来会让用户误以为这些建议已被用于生成 |
| 是否修改 `TaskStudioPreparation` / 两个面板 | ⛔ **本轮不改** | 它们与**现役 Image Studio 共用**；改它属于扩大范围，且不是 Listing Studio 的问题 |

**跨页一致性处理（低成本、不碰共用组件）**：在五问策略区底部放一行说明，把"这一页的策略是真的被用去生成"讲清楚，并指向研究记录：

> 「这里的结论会真正参与本次 Listing 生成。商品研究页/图片创作页里的『AI研究依据』『Listing生成规划』只是参考建议，不会影响这份 Listing。」

## 3. 五个问题的呈现

### 3.0 通用件：证据徽标 + 证据抽屉

#### 3.0.1 徽标（挂在每一条结论后面）

徽标**只用三种**，语义互斥、可核对：

| 徽标 | 中文 | 含义 | 可点开看到 |
|---|---|---|---|
| 🟢 | **依据 2** | 有 **N 条已确认事实**直接支撑 | 事实字段 + 事实值 + "人工已确认" |
| 🟡 | **参考 3** | 有 **N 条研究资料**作为策略参考（不是事实） | 资料原文摘要 + 出现条数 + 强度 + 来源类型 |
| ⚪ | **无依据** | 系统没有找到任何支撑 | 明确说明为什么没有（见各问"证据不足态"） |

> 关于总控 §5 提到的 `E3` 徽标：设计上保留"编号"概念，但**编号放在抽屉内部**（`E1…En` 逐条列出），挂在外面的徽标用中文可读形式。非技术运营看到裸编号 `E3` 无法判断该不该点开；`依据 2`／`参考 3` 能直接看出"有没有、有几条"。

#### 3.0.2 证据抽屉（点击徽标展开，就地展开不跳页）

固定三段式，**第三段是诚实性的关键**：

```
┌─ 依据详情：clear everyday value ─────────────────────────┐
│ 结论类型：表达角度（不是商品事实）                          │
│                                                          │
│ ① 可以直接采信的（已确认事实）            ← 🟢 段          │
│   E1  材质 material = Acacia Wood        人工已确认       │
│   E2  容量 capacity = 360° rotating      人工已确认       │
│                                                          │
│ ② 本次策略参考过的资料（共 8 条）          ← 🟡 段          │
│   E3  [买家评论] 旋转设计方便取用                        │
│       12 条评论提到 · 反复出现 · 占已分析评论 23%          │
│   E4  [买家评论] 台面容易乱                              │
│       3 条评论提到 · 少数提及                             │
│   E5  [关键词] utensil holder · 来自关键词报告            │
│   E6  [竞品页面] ASIN B08XXXX（直接竞品）                 │
│       ⚠ 竞品参考，不等于本商品事实                        │
```

## 4. 推荐 Bullet 顺序（④）

### 4.1 呈现规则

- **只展示一处**：`plan.bulletOrder[]`（＝ `blueprint.benefitOrder`，其来源就是 `strategy.bulletAngles`）。今日蓝图的「卖点顺序」与策略的 `bulletAngles` 是同一份数据，**不得分两处显示**。
- **角色用中文**，不显示 `core_outcome` 这类英文枚举值。
- **每条后面标"能不能兑现"**：有 `primaryFactId` → 🟢 指向一条事实；无 → ⚪ 明说"这次没有对应事实"。
- **必须有一句定性说明**：这是排序建议，不是事实。

**角色中文映射（可直接使用）**

| 内部 role | 界面文案 | 运营含义 |
|---|---|---|
| `core_outcome` | 核心结果 | 先说最重要的好处 |
| `pain_relief` | 解决痛点 | 先说能解决什么麻烦 |
| `use_scenario` | 使用场景 | 先说用在哪 |
| `ease_of_use` | 好不好用 | 先说用起来顺不顺 |
| `proof_or_fit` | 细节佐证 | 先用细节让人放心 |

**界面文案**

```
④ 五点排序建议
   建议按这个顺序写五点，让买家先看到最关心的信息。
   这是"先说哪句"的排序建议，不是商品事实；具体措辞由 AI 决定。

   1  核心结果    understand the main product value    [依据 1]  材质 material
   2  解决痛点    address a common need                [依据 1]  容量 capacity
   3  使用场景    picture a realistic use              [无依据]  这次没有对应事实
   4  好不好用    follow the product details           [依据 1]  尺寸 dimensions
   5  细节佐证    choose with confidence               [依据 1]  配件 included_components

   ▸ 对照当前 Listing 五点顺序
```

### 4.2 与"当前已生成的 Listing"对照（折叠区）

生成之后，运营最想问的是"它到底按这个顺序写了吗"。因此提供一个只读对照，**不做任何自动修改**：

```
▸ 对照当前 Listing 五点顺序
   建议 → 实际
   1 核心结果   →  五点第 1 条  "Acacia wood utensil holder..."     ✓ 一致
   2 解决痛点   →  五点第 2 条  "With 360° rotating design..."      ✓ 一致
   3 使用场景   →  五点第 3 条  （实际使用了"好不好用"角度）          ⚠ 顺序不同
   ⓘ 这里只做对照，系统不会自动改写你的 Listing。
```

### 4.3 确定性兜底时（`fallbackUsed = true`）必须改口

**这是一个已存在的诚实性缺陷，本次一并修正。**

今日界面在策略存在时无条件显示「✓ 已应用到本次 Listing」。但代码事实是：当 `fallbackUsed=true` 时，交付稿由 `buildListingV5FallbackDraft(context, strategy)` 生成，它**只用了** `strategy.bulletAngles[].role`（角色顺序）、`strategy.useCases[0]`、`strategy.keywordIntent.backendOnly`——**文案不是策略写出来的**。

**修正后文案（按实际情况二选一）**

```
✅ AI 生成时：
   ✓ 已应用到本次 Listing：角色顺序、关键词、表达角度

⚠️ 兜底时：
   ⚠ 只应用了结构：五点顺序、关键词。
     本次文案由安全模板生成，不是 AI 按这份策略写的。
```

## 5. 人工确认边界

### 5.1 运营可以做的（都在现有能力内，不新增写操作）

| 动作 | 现有入口 | 说明 |
|---|---|---|
| **重做策略** | 既有 `POST {action:"analyze_strategy", forceStrategy:true}` | 按钮沿用「重新分析策略」，不新增接口 |
| **不采纳** | 不复制、不发布 | 界面已有"需人工复核，不得直接发布" |
| **改方向（强调什么）** | 回到研究阶段修改"补充要求"后重做策略 | `creativePreferences.additionalRequirements` 今天**已经**会进入策略 prompt（`manualDirection`），是真实有效的杠杆 |
| **补证据** | 回研究阶段导入 VOC / 关键词 / 竞品资料 | Planner 只读，不代替采集 |

> ⚠️ **本设计明确不新增**"否决策略""保存我的策略"这类持久化状态。当前 Route 只有 `analyze_strategy` 与 `generate` 两个动作，新增状态属于扩大范围。若产品确实需要"可编辑的策略"，那是下一阶段的新契约，不在本轮。

### 5.2 必须回到研究阶段的（Planner 内不允许就地修改）

| 情况 | 界面引导 |
|---|---|
| 没有可用于 Listing 的已确认事实 | 「请先回到商品研究阶段确认商品事实」+ 返回链接 |
| VOC 证据为 0，② 为什么买 全靠模板 | 「本次没有买家评论资料，建议先补充」 |
| 结论被闸门丢弃（无依据） | 「想让它出现在 Listing 里，需要在研究阶段补上对应资料」 |
| 资料被截断（`textTruncated`） | 「资料过长，AI 只读到前半部分；如需完整使用，请精简或拆分资料」 |

### 5.3 Planner 不得越界（硬性）

1. **不得绕过 `humanReviewRequired`**。快照恒为 `true`，界面"需人工复核"提示不得移除或改写为"已确认"。
2. **不得改变 Validator 结论**。「安全检查通过」等文案由 Validator 决定，Planner 不得因为"证据看起来充分"就改写。
3. **不得把研究资料呈现为商品事实**。所有 VOC/关键词/竞品内容一律标注来源与"不是商品事实"。
4. **不得静默丢弃**。被闸门拒绝的结论必须在「未采用」区可见。
5. **不得提供"一键采纳策略"** 这类自动改写 Listing 的操作。
6. **不得在独立创作模式（无 `taskId`）显示 Planner**——那里没有研究资料，显示即造假。

## 7. 可用性验收清单（交运营自测，8 条）

> 每条都能在不看文档的情况下，靠自己在浏览器里点一遍来判断"过 / 不过"。

1. **我能指出每个卖点来自哪条事实。** 在 ③ 卖什么 里点任意一条的徽标，我能看到它对应的已确认事实字段和值。
2. **我能分清"事实"和"参考"。** 页面上凡是来自买家评论、关键词、竞品的结论，都标着来源；竞品的地方明确写着"竞品参考，不等于本商品事实"。
3. **我能知道这份策略是 AI 想的还是模板套的。** 标题右侧直接写着「AI 归纳」或「固定模板生成 · 未调用 AI」。
4. **我能看到它没有采用的结论和原因。** 「未采用 N 条」点开后，每一条都写明了为什么没用（比如"找不到依据"）。
5. **资料不够时它老实说不够。** 当某项没有证据时，我看到的是"本次没有找到依据 / 请先补充资料"，而不是一段听起来很合理的话。
6. **我明白排序只是建议。** ④ 里明确写着"这是排序建议，不是事实"，并且每条都标了有没有对应事实，我能对照当前 Listing 看它有没有照着写。
7. **我不会误以为策略能自动改稿。** 页面没有任何"一键应用/采纳"按钮；我能改的只有"重新分析策略"和回研究阶段补资料。
8. **一句话能说清这份 Listing 凭什么。** 看完五问，我能用自己的话向同事解释：卖给谁、为什么买、凭什么能说、先说什么、什么不能说。

## 10. 未决问题（需产品/上游拍板）

1. **`coverage` 是否展示？** 语义明确（提到该主题的评论占比），但与"不做百分比"的边界贴得很近。本文默认**不展示**，仅在抽屉原始记录中可选。
2. **② 为什么买 与 痛点 是否合并成一项？** 本文合并（运营视角是同一个问题），但内部是 `purchaseMotivations` 与 `painPoints` 两组数据。若上游认为二者语义需分开，则拆成"② 为什么买"和"②b 在意什么"。
3. **「未采用」的默认展开还是收起？** 本文默认收起（避免噪音），但保证计数可见（"未采用 3 条"）。若追求最大化诚实，可默认展开。
4. **`strength` 阈值文案是否要写进界面？** 当前只在抽屉里显示"反复出现/少数提及/个别提及"。是否加一行"(4 条以上=反复出现)"的解释，取决于运营是否需要知道口径。
