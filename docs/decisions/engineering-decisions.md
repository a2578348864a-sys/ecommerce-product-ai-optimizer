## ADR-001: 确立“证据不等于事实 (Evidence ≠ Fact)”与人工裁决门禁

### 背景与痛点 (Context)
在跨境电商场景下，通用的“端到端 Prompt 生成”工具最大的致命伤是**不可控的事实幻觉**。
当系统抓取到竞品详情、买家评论或供应商宣传文案时，大模型容易：
1. 把竞品独有的专利卖点、配件或功能当成本商品的物理规格；
2. 把买家的主观吐槽情绪当成商品的客观物理缺陷；
3. 随意编造未经证实的认证（如 BPA-free、FDA Approved）。
这在 Amazon 平台极易导致虚假宣传被封店、侵权投诉或高额买家退货。

### 决策 (Decision)
在系统架构层面确立**不可逾越的事实隔离红线**：
- 外部采集的数据一律归类为**证据（Evidence）**，仅作为参考素材，绝不自动升格为**事实（Fact）**；
- 引入**人工事实门禁（Human Gate）**：由熟悉商品的运营人员在控制台逐项打勾核准；
- 仅经过核准的 `Confirmed Facts` 允许进入后续的 Listing 与图片策略生成上下文，未核准信息物理隔离。

### 影响与收益 (Consequences)
- **收益**：从系统源头彻底杜绝了模型无依据夸大和知识幻觉，生成结果具备 100% 事实合规性；
- **代价**：增加了人工核验环节。通过在界面中优化“事实候选比对”卡片与一键批量勾选，将人工耗时压缩至 1 分钟以内。

## ADR-002: 采用确定性正则引擎 (Copy Quality Engine) 替代纯大模型质检

### 背景与痛点 (Context)
传统文本质检通常让大模型“扮演审校专家做自我评估”。但在实践中发现：
1. **自我偏袒与假通过**：大模型倾向于肯定自己生成的文案，即便存在明显的句式重复也容易给出高分；
2. **结构性僵硬病句无法被察觉**：大模型容易生成语法通顺但极不符合地道欧美表达的病句（例如：`opens through its lid mechanism`、`suitable for use at daily hydration`、单数可数名词裸奔等）；
3. **延迟与成本高**：每次质检增加额外的 LLM 网络往返与 Token 开销。

### 决策 (Decision)
自主研发基于确定性正则表达式的 **Copy Quality Engine**，配合模式匹配树拦截 5 大类机器通病：
1. 动词机制套壳（Mechanism overcomplication）
2. 介词与短语搭配错误（Preposition collocations）
3. 场景复读口吃（Redundant scene repetition）
4. 主客体逻辑倒置（Logical reversal）
5. 单数可数名词裸奔（Bare singular countable nouns）

### 影响与收益 (Consequences)
- **收益**：
  - **100% 确定性**：规则白纸黑字，不存在概率性波动；
  - **零延迟与零 Token 成本**：纯本地内存正则计算，耗时 < 5ms；
  - **防假通过**：任何命中坏模式的文案在代码级立即拦截拒绝放行。
- **代价**：需要持续根据真实运营反馈丰富正则词典与语法规则库。

## ADR-003: 选用 SQLite + CAS 乐观并发控制作为本地主存储方案

### 背景与痛点 (Context)
作为面向个人操盘手及中小团队的工作台应用，若引入 PostgreSQL/MySQL 等重型分布式数据库，会显著提高本地部署与运行门槛（需要配置端口、密码、持久卷等）。但如果仅使用普通单机文件读写，又容易在多浏览器标签页并发修改同一商品时发生“后保存覆盖先保存”的脏写踩踏。

### 决策 (Decision)
采用 **Prisma ORM + SQLite** 架构，并在数据表核心记录上实现基于 `storageVersion` 的 **CAS (Compare-And-Swap) 乐观并发控制**：
- 每次写操作必须携带读取时的基准版本号；
- 服务端在 SQL 执行 `WHERE id = ? AND storageVersion = ?`；
- 版本不匹配时主动返回 `409 Conflict`，阻断静默覆盖。

### 影响与收益 (Consequences)
- **收益**：
  - 零配置：单文件数据库随仓库或环境独立运行，备份复制极度轻便；
  - 绝对并发安全：杜绝多标签页或异步任务并发导致的事实数据丢失。
- **代价**：单文件 SQLite 不适合超大规模分布式多实例写入（但在单机工作台场景下完全满足吞吐与可靠性需求）。

## ADR-004: 实施物理隔离的双运行模式 (local_owner / public_showcase)

### 背景与痛点 (Context)
系统需要同时满足两类截然不同的诉求：
1. **本机操盘作业**：需要极致的效率，免密直接操作，支持调用 Chrome CDP 抓取与 1688 CLI 命令；
2. **公开演示展示**：需要面向访客提供体验，但必须绝对保证宿主机安全、保护商业供应链隐私、禁止任意写库。

### 决策 (Decision)
在核心鉴权与路由层实施物理级双运行模式路由：
- **`local_owner`**：绑定本地回环网络，免密登录，完全开放真实采集与主库读写权限；
- **`public_showcase`**：公网访问时强制校验会话，物理切断 `child_process` 命令行执行能力，写操作统一重定向至独立的 JSON 沙箱（`demo-sandbox.json`）。

### 影响与收益 (Consequences)
- **收益**：同一套业务代码与 UI 界面，兼顾了内部操盘手的无感高效与外部公开演示的绝对隔离防护；
- **代价**：在所有涉及系统调用的边界，必须显式编写运行模式判定守卫代码。

## ADR-005: 外部网络采集与数据处理坚持 Fail-Closed 熔断设计

### 背景与痛点 (Context)
爬虫与第三方接口（Amazon 详情、SellerSprite、1688）在遇到网络波动、反爬验证码（Captcha）、登录失效或币种变更时，容易返回不完整或畸形的数据。部分宽松工具会用“默认值”或“空占位符”吞咽错误继续执行，最终导致下游生成荒谬的结果。

### 决策 (Decision)
全面贯彻 **Fail-Closed（遇异常立即安全熔断）** 准则：
- 遭遇验证码或登录墙时，立即中断流程，返回精准的类型化错误码（`needs_user` / `captcha_required`）；
- Amazon 币种非 USD 时拒绝私自折算汇率；
- 采集结果必须经过结构化 Schema 强校验，不满足格式要求绝不进入证据库。

### 影响与收益 (Consequences)
- **收益**：下游 AI 推理与文案生成永远基于可靠、干净的数据，杜绝了由于脏输入导致的隐蔽灾难；
- **代价**：当外部平台风控时需要人工干预介入解决。
